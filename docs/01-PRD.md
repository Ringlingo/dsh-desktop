## 一、产品概述与目标

### 1.1 产品背景

DeepSeek Harness（DSH）是 DeepSeek 出品的 Agent 工具，当前以 `dsh web` 命令在本地启动 Web GUI（默认 `http://127.0.0.1:3080`），需要用户自行安装 Node.js、初始化环境、手动执行命令，使用门槛高、体验碎片化，且缺少进程管理、日志可视、版本更新等桌面应用该有的能力。

本项目将 DSH 封装为一个**便携式 Windows 桌面应用**：双击即用、数据随目录走、无需安装 Node.js、不污染用户环境，并在壳层补齐「工具栏 / 调试工具 / 更新系统」三大能力。

### 1.2 产品定位

> **一句话定位**：一个「把 DeepSeek Harness 装进盒子里的便携桌面启动器」——双击打开就是一个可用的 DSH 工作台，自带进程托管、调试面板、一键更新。

- 对技术用户：提供 IDE 级的调试体验（实时日志、健康检查、一键重启、DevTools）。
- 对普通用户：提供「启动器」式的傻瓜体验（托盘常驻、自动就绪、一键更新，参考绘世启动器）。
- 对组织/重度用户：数据目录（配置/会话/密钥）完全随应用目录走，真正便携，可 U 盘携带。

### 1.3 产品目标

| 维度 | 目标 |
| --- | --- |
| 业务目标 | 以最低使用门槛交付 DSH 的 Windows 桌面形态，让「不会装 Node、不会跑命令」的用户也能使用 DSH |
| 用户目标 | 打开即用：启动 → 自动拉起后端 → 自动进入工作台；后端状态、日志、更新全程可见可控 |
| 技术目标 | 壳（Tauri/Rust）与核心（dsh）彻底分离；核心升级只换 `runtime/` 目录；数据隔离在 `data/`（DSH_HOME） |
| 质量目标 | P0 无已知缺陷上线：启动成功率 ≥ 99%、同源加载 100%、退出零残留进程、更新可回滚 |

### 1.4 成功指标（拟定）

- 首次启动到进入工作台（看到就绪对话页）的中位时间 ≤ 8 秒（本机 SSD）。
- 退出应用后子进程树残留数 = 0（验收必检）。
- 更新失败场景 100% 可回滚到更新前可用版本。
- 后端异常退出（崩溃/被 kill）时，壳能在 5 秒内感知并给出明确提示/恢复入口。
- 空目录环境（首次运行）也能正确初始化 DSH_HOME 结构并正常启动。

### 1.5 产品范围

**范围内（本 PRD 覆盖）**

- 便携壳基础能力：启动编排、就绪检测、托盘、单实例、退出清理、DSH_HOME 隔离。
- 顶栏工具栏与三栏布局改造（左侧导航 / 中间对话区 / 右侧工具区）。
- 调试工具：实时日志、健康检查、进程信息、一键重启、DevTools 开关、环境诊断。
- 版本管理：正确版本显示、检查更新（GitHub API）、一键更新（校验 + 原子替换 + 回滚）、更新日志。
- 设置面板：网络代理、主题、浏览器行为、环境路径（对齐绘世启动器）。
- 账户余额显示：顶栏余额徽标，按当前模型接入 DeepSeek 官方余额接口或 MMX-CLI quota 查询（F-26/F-27，P1）。

**范围外（本版本不做）**

- 修改 DSH 核心业务逻辑（对话、Agent 执行、插件内部实现均继承上游）。
- 多后端实例并行、自定义前端主题框架、移动端适配。
- 插件市场与插件安装的完整 GUI（首版仅提供入口与文档跳转）。

## 二、目标用户与使用场景

### 2.1 目标用户画像

| 画像 | 特征 | 核心诉求 |
| --- | --- | --- |
| **Agent 深度用户** | 已熟悉 DSH/命令行 Agent 工具，想更高效地日常使用 | 启动快、日志可查、重启方便、更新跟得上 RC 节奏 |
| **本地优先/隐私敏感用户** | 关注数据归属，希望密钥、会话留在自己手里 | 数据目录可控、密钥不落公共位置、便携可携带 |
| **非技术探索者** | 不会装 Node/跑命令，但对 AI Agent 工作台感兴趣 | 双击即用、状态可视化、出错有明确指引 |
| **团队/组织分发者** | 需要把同一套 DSH 环境分发给多台机器或拷给同事 | 便携、可整体拷贝、版本统一、可离线更新 |

### 2.2 典型使用场景

1. **首次使用**：用户拿到应用文件夹 → 双击 `dsh-portable.exe` → 看到启动画面/状态栏 → 几秒后自动进入 DSH 工作台。全程零命令行。
2. **日常使用**：用户常驻托盘工作，随时唤起窗口；顶栏一眼看到「后端已就绪 · 端口 38571 · v0.1.0-rc.5」。
3. **排查问题**：对话/插件行为异常时，打开调试面板看实时后端日志、跑健康检查、看进程内存占用，点「重启后端」恢复。
4. **版本升级**：用户收到「发现新版本 dsh-v0.1.1」通知 → 点击一键更新 → 看到下载进度 → 校验通过 → 提示重启；更新失败自动回滚且不影响当前版本使用。
5. **换机器迁移**：用户把整个应用目录拷到另一台 Windows（需 WebView2 运行时）→ 双击直接可用，会话/配置/密钥原样跟随。
6. **端口冲突**：3080 被占用时，应用自动走 `--port 0` 由 OS 分配空闲端口，不报错、不卡死。

## 三、用户故事

> 用户故事按「作为 / 我希望 / 以便」标准格式编写，与需求池编号（见 §4）对应。

- **US-01（P0，启动）**：作为普通用户，我希望双击 exe 后应用自动启动后端并进入工作台，以便我完全不需要手动敲命令行。
- **US-02（P0，状态可见）**：作为用户，我希望顶栏实时显示后端状态、端口与版本，以便我判断"应用是否可用、连的是哪个端口"。
- **US-03（P0，一键重启）**：作为用户，我希望后端卡死/异常时能一键重启，以便我不必结束进程重开整个应用。
- **US-04（P0，调试日志）**：作为技术用户，我希望在调试面板看到后端的实时 stdout/stderr 日志，以便我定位插件或对话流程的问题。
- **US-05（P0，健康检查）**：作为技术用户，我希望一键执行健康检查（端口探测 + host.describe 握手），以便确认后端"活着且能响应"。
- **US-06（P0，更新发现）**：作为用户，我希望应用能对比 GitHub 上的 dsh 版本并提示"有新版本"，以便我知道何时该升级。
- **US-07（P0，安全更新）**：作为用户，我希望一键更新能校验完整性并在失败时回滚，以便我永远有一个可用的版本兜底。
- **US-08（P0，数据隔离）**：作为隐私敏感用户，我希望所有数据（配置/密钥/会话）都写进应用目录内的 data/，以便不污染我的用户主目录、可整体拷贝。
- **US-09（P0，干净退出）**：作为用户，我希望退出应用时后端进程被彻底清理，以便不残留占用端口的幽灵进程。
- **US-10（P0，托盘常驻）**：作为用户，我希望关窗后应用留在托盘，以便我随时快速回到工作台且后端不中断。
- **US-11（P0，单实例）**：作为用户，我希望重复双击只聚焦已有窗口，以便不启动多个后端造成资源浪费。
- **US-12（P1，环境诊断）**：作为技术用户，我希望运行一键诊断（node 版本 / 端口占用 / 磁盘空间 / DSH_HOME 路径），以便快速定位"为什么起不来"。
- **US-13（P1，疑难解答）**：作为非技术用户，我希望点「疑难解答」就能自动扫描常见问题并给出修复建议，以便不求助别人。
- **US-14（P1，设置）**：作为用户，我希望在设置面板配置代理、主题、是否用系统浏览器打开外链、环境路径，以便适配我的网络与偏好。
- **US-15（P1，更新通知）**：作为用户，我希望启动时静默检查更新，有新版才提示，以便不打扰我的正常使用。
- **US-16（P2，离线更新）**：作为离线环境用户，我希望能手动导入更新包完成升级，以便无外网时也能升级。
- **US-17（P2，插件入口）**：作为技术用户，我希望左侧有插件入口并可跳转官方插件文档/本地配置位置，以便扩展 DSH 能力。
- **US-18（P1，DeepSeek 余额）**：作为使用 DeepSeek 模型的用户，我希望在顶栏看到 DeepSeek 账户余额与可用状态（总/赠送/充值），以便掌握额度消耗、及时充值，无需登录官网。
- **US-19（P1，MiniMax 余额）**：作为使用 MiniMax 模型的用户，我希望在顶栏看到 MiniMax Token Plan 剩余额度（经 MMX-CLI 查询），以便掌握配额余量、避免额度超限中断。

### 4.2 P0 需求明细（首版必须）

#### F-01 启动编排与就绪检测

| 项 | 内容 |
| --- | --- |
| **功能描述** | 应用启动后，Rust 壳 spawn 内置 `runtime/node.exe`（≥22.19）执行 dsh 后端（`apps/cli` 产物，命令 `dsh web --port 0`）；监听子进程 stdout，解析就绪行 `dsh web: http://127.0.0.1:PORT`，将 WebView 导航到该同源 URL。 |
| **交互说明** | 就绪前显示启动状态（「正在启动后端…」）；解析成功前不加载任何页面；解析失败/超时（如 30s）显示错误页并给出「查看日志 / 重启」操作。 |
| **验收标准** | ① 首次启动成功进入工作台；② 就绪 URL 必须为 `http://127.0.0.1:PORT` 且端口由 OS 分配（`--port 0`），绝不使用硬编码 3080；③ 30s 内未就绪则进入错误态并提供日志入口；④ WebView 加载 URL 前做校验（loopback + http scheme），加载后 `GET /api/…` 无 403。 |

#### F-02 DSH_HOME 数据隔离

| 项 | 内容 |
| --- | --- |
| **功能描述** | 启动子进程前设置环境变量 `DSH_HOME=<应用目录>/data`，并确保目录结构（`settings.yaml` / `.credentials.yaml` / `profiles/` / `storages/` / `sessions/` / `attachments/` / `.agent-presets/`）在首次运行时正确初始化。 |
| **交互说明** | 无用户交互；数据目录损坏/不可写时，在顶栏与错误页给出明确路径提示。 |
| **验收标准** | ① 首次运行后 `data/` 下出现完整目录结构；② 应用目录被整体拷贝到新机器（同架构 Windows）后，会话/配置/密钥原样可用；③ 代码中不存在回落到用户主目录 `~/.dsh` 的路径分支；④ 应用卸载/删除目录后，用户主目录内不残留本项目产生的数据文件。 |

#### F-03 托盘常驻

| 项 | 内容 |
| --- | --- |
| **功能描述** | 关闭主窗口默认最小化到系统托盘；托盘图标 + 菜单（显示主窗口 / 打开调试面板 / 检查更新 / 退出）。 |
| **交互说明** | 点关闭按钮 → 窗口隐藏、后端继续运行；点托盘图标 → 恢复窗口；菜单「退出」→ 执行 F-05 完整退出。 |
| **验收标准** | ① 关窗后窗口隐藏且后端仍可访问（再次打开前端无重载问题）；② 托盘菜单各项可用；③ 「退出」后进程树清理干净（见 F-05）。 |

#### F-04 单实例

| 项 | 内容 |
| --- | --- |
| **功能描述** | 使用 Tauri 单实例插件；第二个实例启动时向首个实例发送「聚焦窗口」信号后退出。 |
| **交互说明** | 重复双击 exe 只出现一个窗口，且已有窗口被唤起置前。 |
| **验收标准** | ① 连续启动两个实例，进程数只有一个后端子进程；② 第二个实例会把已有窗口带到前台；③ 并发场景（快速双击）无竞态导致双后端。 |

#### F-05 退出清理

| 项 | 内容 |
| --- | --- |
| **功能描述** | 应用退出时终止整个子进程树（node.exe 及其孙进程，含 node-pty 可能衍生的 shell），保证端口与资源完全释放。 |
| **交互说明** | 退出确认后可立即退出；托盘「退出」与系统关机/注销均触发清理。 |
| **验收标准** | ① 退出后 `netstat` 中原端口无监听；② 任务管理器中无残留 node.exe / shell 子进程；③ 正常退出与强制终止（杀壳进程）两种路径都不允许残留后端（强制路径尽量兜底，如子进程设独立 Job Object）。 |

#### F-06 顶栏工具栏

| 项 | 内容 |
| --- | --- |
| **功能描述** | 顶栏常驻工具栏，从左到右：后端状态灯（启动中/就绪/异常）+ 端口 + 版本 + 调试开关 + 重启后端 + 检查更新 + 更新按钮（有更新时高亮）。 |
| **交互说明** | 状态灯三色：灰=启动中、绿=就绪、红=异常；端口可复制；重启需二次确认；更新按钮在检测到新版时变为高亮可点。 |

## 六、非功能需求

### 6.1 性能

- 首次启动到就绪（工作台可用）中位时间 ≤ 8s（本机 SSD，冷启动含 node 加载）。
- 顶栏状态刷新延迟 ≤ 1s；日志行渲染不卡顿（万行级滚动流畅）。
- 应用常驻内存开销 ≤ 200MB（壳层本身，不含后端）。
- 更新下载采用流式写盘，不一次性全载内存。
- 余额接口调用节流防抖：自动刷新默认 30min，手动「立即刷新」间隔 ≥5s；查询在后台线程执行，不阻塞 UI 与对话。

### 6.2 安全

- 后端仅绑定 `127.0.0.1`，不对外网暴露。
- 凭证文件（`.credentials.yaml`）仅在应用目录 `data/` 内读写；日志中禁止打印密钥/令牌明文。
- WebView 仅加载就绪信号产出的 `http://127.0.0.1:PORT` 同源 URL；禁止 `file://`、禁止自定义 scheme（防 /api 403 与安全边界破坏）。
- 更新包必须 SHA256 校验，校验失败拒绝安装。
- 原生壳不应以管理员权限运行（如无必要）；不创建全局注册/自启动项。
- 余额查询仅走 HTTPS（`https://api.deepseek.com/user/balance`）；API Key 仅用于请求头 / MMX-CLI 登录参数，禁止明文写入任何日志、更新日志或错误提示。
- 无网络 / 接口失败 / 认证失败时，余额位静默降级显示 `--`，不阻塞启动、对话与更新等任何主流程。

### 6.3 便携性

- 整包为单个目录，可拷贝/移动/以 U 盘携带；唯一外部依赖为系统 WebView2 运行时（Tauri 2 要求）。
- 数据零外溢：DSH_HOME 始终指向应用目录 `data/`；不写注册表关键业务数据、不写用户主目录业务文件。
- 移动目录后重新启动，会话/配置/密钥保持可用。

### 6.4 稳定性

- 后端崩溃可感知、可一键恢复（P1）。
- 更新失败可回滚，任何时刻存在可用版本。
- 断电/强杀场景下：`data/` 采用合理写入策略（日志追加、更新用「备份+替换+提交标记」），残留半状态可被疑难解答扫描识别。
- 应用整体异常时不弹裸 Rust panic，所有错误走统一错误页/提示。

### 6.5 兼容性

- Windows 10 1809+ / Windows 11 x64（首版仅 x64）。
- WebView2 Runtime 缺失时给出下载指引（而非白屏）。
- 内嵌 Node ≥ 22.19，随包分发，不依赖系统 Node。

### 6.6 可维护性

- 壳与核心彻底分离：`src-tauri/`（壳）、`runtime/`（node + dsh 核心）、`data/`（运行时数据）。
- 核心升级仅替换 `runtime/`，壳代码零改动（接口为 `dsh web` stdout 协议 + 目录约定）。
- 所有对外关键行为（端口解析、semver 比较、SHA256、目录初始化）提供单元测试。

## 七、质量红线（无 Bug 保障）

以下为**一票否决级**红线，任何实现不得突破；每项均进入自动化/人工验收清单：

| # | 红线 | 说明 | 验收方式 |
| --- | --- | --- | --- |
| R1 | **WebView 必须加载 `http://127.0.0.1:PORT` 同源 URL** | 严禁 `file://` 或自定义 scheme 加载前端；否则 `/api/*` 全部 403。加载前强制校验 scheme=http、host=loopback、端口来自就绪行。 | 自动化断言 + 手工验证 /api 请求 200 |
| R2 | **DSH_HOME 必须指向应用目录 `data/`，禁止回落 `~/.dsh`** | 壳层以显式环境变量注入 DSH_HOME；代码中不得存在"无 DSH_HOME 时用默认路径"的分支。 | 代码审查 + 首启后检查 `data/` 结构 + 检查用户主目录无残留 |
| R3 | **退出必须杀干净子进程树** | 含 node.exe 及其孙进程（node-pty 衍生的 shell）。采用 Job Object（Windows）兜底，确保强杀壳进程也不残留。 | 退出后 `netstat` 端口释放 + 进程列表无残留 |
| R4 | **版本显示不得使用 `host.describe().version`** | 该字段硬编码 '0.0.1' 不可信；一律读 `runtime/apps/cli/package.json`（回退 `dsh --version`）。 | 界面快照比对 + 代码审查 |
| R5 | **更新必须具备校验 + 原子替换 + 回滚** | SHA256 不匹配拒绝安装；替换前备份；新版本自检失败自动回滚；任何时刻存在可用版本。 | 注入损坏包/断网/中断场景测试 |
| R6 | **更新过程不得阻塞 UI** | 下载/校验/替换全部后台线程；UI 仅接收进度事件。 | 更新期间 UI 可交互测试 |
| R7 | **日志不得输出敏感信息** | 密钥/令牌/token 禁止写入日志与更新日志。 | 代码审查 + 日志抽样扫描 |
| R8 | **单实例，绝不双后端** | 并发启动只保留一个后端进程。 | 并发启动 50 次压力测试 |
| R9 | **无裸崩溃** | 任何失败路径进入统一错误 UI，不弹 Rust panic / 白屏。 | 注入后端崩溃/磁盘满/端口异常场景 |
| R10 | **启动协议解析严格** | 仅接受与 `dsh web: http://127.0.0.1:PORT` 匹配的 stdout 行为就绪信号，误匹配必须防御（如开发服务器输出干扰）。 | 正则/协议测试覆盖误报场景 |
| R11 | **余额凭据与请求安全** | 余额相关凭据（DeepSeek API Key / MINIMAX_API_KEY）仅用于 HTTPS 请求头或 MMX-CLI 登录参数，任何日志（含更新日志）、错误提示不得出现 token/密钥明文；查询失败（网络/认证/额度）一律静默降级显示 `--`，不抛错、不阻塞 UI。 | 代码审查 + 日志抽样扫描 + 断网/错误密钥/额度超限场景测试 |

**质量流程要求**：P0 全部红线项进入 CI 自动化测试；发布前须完成「后端崩溃 / 更新失败回滚 / 端口占用 / 无 WebView2 / 磁盘空间不足 / 日志敏感信息扫描」六类演练。
